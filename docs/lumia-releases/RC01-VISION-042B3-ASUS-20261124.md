## Preparación segura de QA en una carpeta distinta

**No ejecutar el launcher RC01 desde `LUMIA-ASUS`.** Esta evaluación se hace exclusivamente en un segundo checkout. Si Git/Node ya están instalados y la carpeta QA aún no existe, ejemplo en PowerShell:

```powershell
$qa = Join-Path $env:USERPROFILE 'LUMIA-RC01-QA'
$original = Join-Path $env:USERPROFILE 'LUMIA-ASUS'
if (-not (Test-Path -LiteralPath $original -PathType Container)) { throw 'Falta la carpeta ASUS original' }
if (Test-Path -LiteralPath $qa) { throw 'Ya existe carpeta RC01-QA; no sobrescribirla' }
$sha = (git -C $original rev-parse HEAD).Trim()
if ($sha -ne '1580a5182eba540893e35e37065be77da4ed014c') { throw "ASUS original cambió: $sha" }
git clone --single-branch --branch release-candidate/lumia-vi042b3-asus-20261124 https://github.com/ingeniusvictor/orbi-jarvis-agent-lab.git $qa
Set-Location $qa
git status --porcelain
node scripts/lumia-private-avatar-assets-rc01.mjs --doctor --from $original
```

Si decides ensayar el avatar completo, la copia de **VRM y 17 clips privados** desde tu instalación original hacia la QA es **explícita**, local y verifica SHA-256 sin sobrescribir lo ya existente:

```powershell
node scripts/lumia-private-avatar-assets-rc01.mjs --copy --from $original
npm.cmd ci --onnxruntime-node-install-cuda=skip
.\INICIAR_LUMIA_VISION_RC01_ASUS.cmd
```

La instalación original es **fuente de solo lectura para esta copia**, no se cambia Git ni Ollama en la ASUS principal. El launcher RC01 verifica que no se está ejecutando desde la carpeta protegida y se niega a iniciar si faltan los assets privados. El instalador normal de rostros puede descargar BlazeFace oficial si aún no existe en la QA; cámara/micrófono permanecen sujetos a autorización desde la interfaz.

## Validación y aceptación antes de modificar original
1. **CI Windows y Ubuntu** de `.github/workflows/lumia-vision-rc01-promotion.yml`: dependencias, pruebas sintéticas 0/1/2 rostros, clasificador de posturas, WASM, build y lint.
2. Ejecutar en **checkout QA separado de LUMIA-ASUS**, con assets privados autorizados de la app. Arrancar `INICIAR_LUMIA_VISION_RC01_ASUS.cmd`. La webcam no se inicia automáticamente. Si el instalador de modelo requiere red, informar y validar descarga pública pinneada; nunca copiar secretos.
3. **QA física ASUS** con Qwen 2B, Whisper/Kokoro, avatar intactos, cámara autorizada 3 min y cierre/cancelación. Preguntar «¿Cuántas personas ves?» para una y dos personas visibles, revisar `[lumia:vision-vi042a]` `sameJpeg:true` y foto única; preguntar «¿Tengo el brazo derecho levantado?» cuando sea visible; revisar no alucinar brazos abajo fuera de encuadre. Verificar detector OFF/error, expiración 180s y no persistir fotos.
4. Preparar backup **antes** de modificar la carpeta original: anotar SHA, comprobar cambios locales y librerías/paths privados, conservar rollback verificable. El backup es de runtime y archivos propios **sin subir voz, VRM ni fotos**.
5. **Presentar al propietario diff, resultados QA y rollback y obtener su autorización de la actualización específica**. Después, y solo después, promover el SHA a la línea estable y actualizar original ASUS en operación controlada.
6. HP y CPU pueden quedar `pending` como despliegue escalonado del **mismo código**, no afirmar compatibilidad sin pruebas físicas.
